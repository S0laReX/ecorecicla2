# US 10 · Calificaciones de recolecciones

Sprint 3, épica 6. Web y móvil usan las mismas pantallas responsive y la API MVC.

## Comportamiento

- Solo una de las dos partes de una recolección confirmada puede calificar a la otra.
- Cada participante puede registrar una calificación entera de 1 a 5 estrellas, una sola vez por recolección.
- La calificación no tiene comentario ni datos enviados por el cliente aparte de las estrellas.
- El servidor verifica la sesión vigente, la participación y el estado confirmado; no confía en el usuario receptor enviado desde el cliente.
- El promedio se calcula desde las calificaciones recibidas y se consulta desde el perfil. Si no hay registros, la API responde `average: null`, `count: 0` y la interfaz muestra el estado vacío.
- `/calificaciones` lista recolecciones confirmadas que el usuario actual aún no ha calificado. `/perfil` muestra el promedio y el número de calificaciones recibidas.
- Las dos rutas se adaptan a móvil y escritorio y consumen la misma API.

## Diseño

Se reutiliza el modal compartido con selección accesible de estrellas, conforme a la referencia Figma `15:5725`. El resumen de perfil presenta el promedio y el número de opiniones. En móvil, las tarjetas se apilan y el acceso permanece en la navegación adaptable.

## API

- `GET /api/ratings/pending` — lista confirmaciones propias pendientes.
- `POST /api/ratings/reservations/:reservationUUID` — cuerpo estricto `{"score": 1}` a `{"score": 5}`.
- `GET /api/ratings/me` — promedio del perfil autenticado (`average` puede ser `null`; `count` es cero cuando no hay opiniones).

Errores relevantes: 401 sesión inválida; 403 rol no permitido; 404 la reserva no pertenece al usuario; 409 la recolección no está confirmada o ya existe una calificación; 422 UUID o puntuación inválida.
