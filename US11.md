# US 11 · Administración de cuentas

Sprint 3, épica 6. El administrador gestiona usuarios y empresas desde la misma API usada por escritorio y móvil.

## Comportamiento

- `/admin/cuentas` lista cuentas de usuario y empresa con búsqueda, filtro de estado y paginación. Los administradores no aparecen como cuentas administrables.
- El estado visible es `Activo` para usuarios; para empresas es `Pendiente`, `Aprobada` o `Rechazada`. `Suspendida` prevalece en ambas clases y se conserva el estado de verificación original.
- Solo un administrador con sesión vigente puede listar, suspender o reactivar cuentas.
- Suspender cambia el estado, incrementa la versión del token y revoca todas las sesiones vigentes. Los intentos posteriores de iniciar sesión, renovar sesión, publicar, aceptar una recolección o consultar funciones autenticadas reciben el error de cuenta suspendida.
- Reactivar permite iniciar sesión de nuevo. Las sesiones anteriores continúan revocadas y cada dispositivo debe autenticarse otra vez.
- Las publicaciones, reservas y recolecciones no se eliminan ni se modifican al cambiar el estado.
- Cada cambio exitoso se guarda en `AccountStatusAudit` dentro de la misma transacción, con cuenta afectada, administrador, estado anterior, estado nuevo y fecha UTC.

## Diseño

La página `/admin/cuentas` sigue la referencia Figma `15:3196`: panel administrativo, búsqueda, estados y acciones. En escritorio las cuentas se presentan en filas; en móvil los datos se apilan y la acción ocupa el ancho disponible. La confirmación explica el cierre de sesiones y la conservación del historial.

## API y migración

- `GET /api/admin/accounts?page=1&limit=10&search=&status=ALL`
- `PATCH /api/admin/accounts/:userUUID/status` con cuerpo estricto `{"status":"SUSPENDED"}` o `{"status":"ACTIVE"}`.
- La migración aditiva `database/007_account_status_audit.sql` crea el registro persistente de cambios.
- `npm run migrate` aplica la migración. `start-local.ps1` la verifica automáticamente antes de iniciar backend y frontend.

Los errores distinguen autenticación (401), autorización (403), cuenta inexistente (404), transición repetida o desactualizada (409) y parámetros/cuerpo inválidos (422).
